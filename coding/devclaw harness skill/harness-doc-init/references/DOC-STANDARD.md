## 1. 文件命名规范

### 1.1 入口文档命名

| 文件名 | 允许位置 | 用途 |
|--------|---------|------|
| `README.md` | **仅根目录** | 面向人类的项目介绍入口 |
| `AGENTS.md` | 根目录 + 所有模块目录 | 面向 Agent 的任务路由和约束 |
| `ARCHITECTURE.md` | 根目录 + 复杂模块 | 代码地图、边界、不变量 |

**默认规则**：模块入口统一使用 `AGENTS.md`，不在子目录新增 `README.md`。

**例外**：如果模块是独立发布的包（npm package、crate、PyPI 包），其目录下可保留 `README.md` 作为包发布元数据，但 Agent 导航入口仍使用 `AGENTS.md`。

### 1.2 专题文档命名

- 使用 kebab-case：`sso-login-flow.md`、`release-guide.md`
- 名称应自解释用途，不用编号前缀
- 按类型放入对应子目录：
  - `docs/reference/` — 稳定事实说明（API、协议、架构分析）
  - `docs/guidance/` — 操作手册、联调流程、SOP
  - `docs/plans/` 或 `docs/adr/` 或 `docs/rfcs/` — 设计决策记录（按仓库习惯选择）

## 2. 文档分层模型

### 2.1 最大五层（按需裁剪）

```
L0  根入口      AGENTS.md + README.md + ARCHITECTURE.md
L1  中层索引    docs/AGENTS.md
L2  模块入口    <module>/AGENTS.md
L3  专题知识    docs/reference/ + docs/guidance/ + docs/plans|adr|rfcs/
L4  开发期技能  .skills/（或 .claude/、.cursor/ 等 Agent 技能目录）
```

### 2.2 按复杂度裁剪

| 项目复杂度 | 必需文档 | 可选文档 |
|-----------|---------|---------|
| 小型 | 根 AGENTS.md | ARCHITECTURE.md |
| 中型 | + 模块 AGENTS.md | + docs/AGENTS.md |
| 大型 | + docs/AGENTS.md + reference/guidance | + ARCHITECTURE.md（模块级） |
| 特大型 | + .skills/ + plans/ | + 子模块 AGENTS.md |

### 2.3 渐进式披露原则

- 每层文档只包含**本层职责**的信息
- 需要更深入的信息时，提供明确的**跳转引用**
- Agent 从根 AGENTS.md 出发，最多 2 次跳转到达任何重要信息
- 模块级文档**不重复**根级约束，只引用

## 3. 各类文档职责

### 3.1 根 AGENTS.md

**目标行数**：80-150 行（不超过 200 行）

必须包含的章节：

| 章节 | 内容 |
|------|------|
| 如何使用本文件 | Agent 和人类的阅读起点说明 |
| 项目简介 | 一段话说明项目、技术栈 |
| 文档体系 | 分层表格，列出所有层级入口 |
| 知识导航表 | "我要做什么 → 去哪里看"格式 |
| 核心约束 | 从代码分析中提取的具体规则 |
| 代码质量回压 | hook 安装方式和触发规则 |

### 3.2 ARCHITECTURE.md

**参考**：[matklad 方法论](https://matklad.github.io/2021/02/06/ARCHITECTURE.md.html)

必须包含的章节：

| 章节 | 内容 |
|------|------|
| Bird's Eye View | 一段话 + ASCII 架构图 |
| Code Map | 每个重要目录的职责 + Architecture Invariant |
| Cross-Cutting Concerns | 认证、存储、可观测性等横切关注点 |

**Architecture Invariant** 是本文档最重要的部分——它描述代码中**刻意不存在**的东西和**必须保持**的约束。

### 3.3 模块 AGENTS.md

**目标行数**：50-150 行

必须包含的章节：

| 章节 | 内容 |
|------|------|
| 模块定位 | 一句话说明职责 |
| 知识导航 | 本模块相关的跳转表 |
| 目录结构 | 关键子目录和职责 |
| 本地约束 | 仅适用于本模块的规则 |
| 常用命令 | dev/test/build/lint 命令 |

### 3.4 docs/AGENTS.md

**目标行数**：50-120 行

必须包含的章节：

| 章节 | 内容 |
|------|------|
| 阅读顺序 | Agent / 人类各从哪里开始 |
| 文档分层 | 指向上下游层级 |
| 按任务导航 | 聚合所有 reference/guidance 的导航表 |
| 当前专题文件 | docs/ 的实际文件树 |
| 维护规则 | 新增文档的分类归属规则 |

## 4. 写作规范

### 4.1 语言

- 跟随仓库已有文档的语言（中文仓库用中文，英文仓库用英文）
- 代码、文件路径、包名、技术术语保留英文
- 默认跟随用户的语言偏好

### 4.2 标题格式

- AGENTS.md：`# AGENTS.md — <描述>`（如 `# AGENTS.md — 仓库文档总入口`）
- ARCHITECTURE.md：`# <ProjectName> Architecture`
- 模块 AGENTS.md：`# AGENTS.md — <module>/ <描述>`

### 4.3 知识导航表

统一使用"我要做什么 → 去哪里看"格式：

```markdown
| 我要做什么 | 去哪里看 |
|---|---|
| 第一次进入仓库 | `README.md` |
| 理解代码架构 | `ARCHITECTURE.md` |
```

### 4.4 核心约束写法

每条约束必须：
- **具体**：让 Agent 能明确判断自己是否违规
- **可执行**：有对应的检查手段（lint rule、hook、test）
- **有来源**：从代码/配置中提取，不是编造

好的约束："代码文件行数上限 600 行（由 `.hooks/check-file-length.sh` 检查）"
差的约束："保持代码文件合理长度"

### 4.5 交叉引用

- 使用相对路径：`../docs/reference/xxx.md`
- 从当前文件出发计算路径
- 引用必须指向实际存在的文件

### 4.6 目录结构展示

使用 tree 格式的代码块，每个条目附简短注释：

```markdown
```text
project/
├── src/           # 源代码
├── tests/         # 测试
└── docs/          # 文档
```　
```

## 5. 质量检查清单

生成文档后逐项核对：

### 导航完整性
- [ ] 从根 AGENTS.md 可导航到所有重要模块
- [ ] 知识导航表覆盖开发者 80% 的常见任务
- [ ] 每份文档都有跳转到相关文档的引用

### 内容准确性
- [ ] 文件路径与实际代码一致
- [ ] 命令可在对应目录执行
- [ ] 目录结构与实际代码一致
- [ ] 类型名/接口名在对应文件中存在

### 约束可执行性
- [ ] 核心约束可以通过 lint/hook/test 检查
- [ ] 约束来源于代码分析，不是编造
- [ ] 生成代码文件不要手改等规则有对应的工具支持

### 层级规范
- [ ] 模块文档不重复根级约束
- [ ] 根 AGENTS.md 不超过 200 行
- [ ] 只有根目录使用 README.md
