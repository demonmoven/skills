# 生成范围

本阶段只回答一个问题：本次应该为哪些业务单元生成或补充单测，并输出后续阶段可直接消费的 `TARGETS`。

## 职责边界

本阶段负责：

- 判断范围来自 `diff` 还是 `非 diff`。
- 展开候选业务文件，并过滤不应生成单测的文件。
- 将候选文件映射到函数、方法、类成员或语言定义的最小可测单元。
- 输出 `TARGETS` 和必要的 diff 定位信息。

本阶段不负责：

- 识别 `LANG` 或加载语言 prompt。
- 读取项目约定文档、feature spec 或测试风格。
- 判断真实业务缺陷、生成 `BUG_MAP` 或设计测试用例。
- 编写、运行、修复测试。
- 执行编译、构建等任何手段验证代码是否可编译。
- 加载或过滤覆盖率配置（由 Step6 负责）。

## Phase 1 判断范围类型

范围只分为两类：

| 类型         | 触发条件                                                                                      | 输入来源                                                     |
|------------|-------------------------------------------------------------------------------------------|----------------------------------------------------------|
| `diff`     | 用户要求基于 diff、变更、工作区、MR、分支差异、本地未提交改动生成或补充单测；用户未指定范围但存在本地业务变更；或用户指定的函数、文件、目录、包、模块中存在本地业务变更   | Git diff、本地 staged / unstaged / untracked 文件，可与用户显式范围取交集 |
| `non_diff` | 用户明确指定函数、方法、类、文件、目录、包、模块、`${TEST_SCOPE}`，且该范围内没有可用业务变更；或用户选中 / 提及已有测试函数、测试类、测试文件且没有要求结合变更 | 用户显式范围，或从测试入口反查出的业务目标                                    |

无法进入任一类型时，进入 `need_clarification`：要求用户选择函数、文件、目录、包、diff 基线或自定义筛选规则。不得自行扩大到全仓库扫描。

## Phase 2 计算候选范围

### 2.1 非 diff 范围

`non_diff` 按输入来源展开：

- 显式函数、方法、类或对象：定位到所在业务源文件，并记录具体符号。
- 显式文件：直接作为候选文件。
- 显式目录、包或模块：枚举其中符合 `LANG` 的业务源文件，再执行过滤。
- `${TEST_SCOPE}`：按其原始语义解析，不得改写为更大范围。
- 测试入口：读取用户提及的测试函数、测试类或测试文件，通过命名、路径、import / require / `@testable import`、fixture
  构造和被调用符号反查业务目标；无法唯一定位时，列出候选并要求用户确认。

如果用户显式指定的是文件、目录、包或模块，必须同时检查该范围内是否存在 `cached`、`unstaged` 或 `untracked`
业务变更。存在变更时，本次范围类型转为 `diff`，候选文件取“用户显式范围”和“本地变更业务文件”的交集；交集为空时，回到`non_diff`
，并在 `fallback_notes` 说明指定范围内没有本地变更。

非 diff 范围没有 diff hunk。后续映射目标时，应依据用户指定符号、测试入口反查证据或语言 prompt 的目标函数提取规则。

### 2.2 Diff 范围

`diff` 范围只计算候选文件和必要的 hunk 位置，不传递完整 patch。

比较规则：

- 同时指定 `source_ref` 和 `target_ref`，且语义是分支或 MR：使用 `target_ref...source_ref`。
- 同时指定 `source_ref` 和 `target_ref`，且用户明确要求两个 commit 直接比较：使用 `target_ref source_ref`。
- 只指定 `target_ref`：使用 `target_ref...HEAD`；若 `target_ref` 与 `HEAD` 之间无 merge-base，回退为两点比较
  `target_ref HEAD`。
- 只指定 `source_ref` 但没有基线：要求用户补充 `target_ref`，或改用本地未提交变更。
- 未指定 commit、branch 或 MR 基线：分析本地 `cached`、`unstaged` 和 `untracked` 业务文件。
- 用户同时指定文件、目录、包或模块且存在本地变更：先展开用户显式范围，再与本地 `cached`、`unstaged`、`untracked` 业务文件取交集；后续
  `TARGETS` 只来自交集。

允许使用的命令形态：

```bash
git diff --name-status --diff-filter=ACMR <range>
git diff --unified=0 <range> -- <file_path>
git diff --cached --name-status --diff-filter=ACMR
git diff --cached --unified=0 -- <file_path>
git ls-files --others --exclude-standard
```

约束：

- 不得为了计算 diff 执行 `checkout`、`switch`、`reset`。
- 删除文件不进入 `TARGETS`；仅可作为后续分析上下文。
- 未跟踪文件只能作为新增候选文件，不得伪造 hunk。
- 完整 diff 正文不得写入本阶段输出。

## Phase 3 文件过滤

所有候选文件都必须经过过滤。过滤后目标文件超过 20 个，且用户没有显式限定范围时，必须要求用户缩小范围。
若 `EXEC_SOURCE = PIPELINE`，则按字典序排序挑选前 20 个文件。

默认排除以下文件：

- 目录段包含 `kitex_gen`、`thrift_gen`、`hertz_gen`、`rpc_gen`、`node_modules`、`vendor`、`dist`、`build`、`out`、`target`、
  `__pycache__`。
- 自动生成的 `protobuf_gen`，以及明确为自动生成的 `pb` 子目录。
- 文件前 5 行包含 `// Code generated`、`// DO NOT EDIT`、`/* Auto-generated */`、`# This file is generated`、
  `// Generated by`、`@generated`。
- 仅做启动、依赖注入或组装的入口文件。
- 仅做导出聚合的 `index.{js,ts}`、`mod.rs` 等文件。
- 仅含类型声明的 `*.d.ts` 或语言 prompt 明确排除的声明文件。

用户显式要求覆盖被排除文件时，说明风险后以用户指令为准。

## Phase 4 映射 TARGETS

过滤后的候选必须映射为 `TARGETS`。映射粒度遵循语言 prompt 的最小可测单元。

Diff 范围：

- 优先把每个有效 hunk 映射到所在函数、方法、类成员或语言定义的目标单元。
- 函数签名变化计入目标单元。
- 同一目标单元命中多个 hunk 时合并为一个 `TARGETS` 项，并保留 hunk 定位信息。
- hunk 无法可靠映射时退回文件级目标，并写明 `fallback_reason`。

非 diff 范围：

- 用户指定符号时，直接映射为目标单元。
- 用户指定文件、目录、包或模块时，按语言 prompt 提取可测目标单元。
- 测试入口反查时，只保留与用户选中测试最相关的业务目标。
- 无法确认目标单元时，停止并要求用户补充范围。

## Phase 5 输出结构

本阶段只输出以下字段：

| 字段               | 必填       | 含义                                           |
|------------------|----------|----------------------------------------------|
| `scope_type`     | 是        | `diff` / `non_diff`                          |
| `TARGETS`        | 是        | 最终生成范围，结构见下文                                 |
| `diff_context`   | diff 时必填 | 后续按需获取局部 diff 或读取未跟踪文件的最小信息；非 diff 时为 `null` |
| `fallback_notes` | 否        | 范围过宽、hunk 无法映射、测试入口无法唯一反查等说明                 |

不得输出完整 patch。

### TARGETS 结构

`TARGETS` 是数组。每个元素必须包含：

| 字段                | 必填 | 含义                                                                      |
|-------------------|----|-------------------------------------------------------------------------|
| `file_path`       | 是  | 业务源文件路径，使用仓库相对路径                                                        |
| `target_type`     | 是  | `function` / `method` / `class` / `file` / 语言 prompt 定义的最小可测单元          |
| `symbol`          | 是  | 目标符号名；文件级目标使用文件名或语言 prompt 规定的标识                                        |
| `locator`         | 是  | 可定位证据，例如起始行、签名行、类名 + 方法名、测试入口反查证据                                       |
| `source`          | 是  | `explicit` / `test_entry` / `diff_hunk` / `untracked` / `caller_callee` |
| `reason`          | 是  | 为什么该单元应进入本次生成范围                                                         |
| `hunks`           | 是  | 命中的 hunk 行号范围；非 diff 或无 hunk 时为空数组                                      |
| `fallback_reason` | 否  | 退回文件级目标或无法精确映射的原因                                                       |

### diff_context 结构

`diff_context` 只保留后续定位局部 diff 所需的信息：

| 字段      | 必填 | 含义                      |
|---------|----|-------------------------|
| `files` | 是  | 过滤后的 diff 文件列表及 hunk 位置 |

`files[]` 字段：

| 字段          | 必填     | 含义                                                                    |
|-------------|--------|-----------------------------------------------------------------------|
| `file_path` | 是      | 仓库相对路径                                                                |
| `status`    | 是      | `A` / `C` / `M` / `R` / `untracked`                                   |
| `mode`      | 是      | `merge_base` / `endpoint` / `cached` / `unstaged` / `untracked`       |
| `range`     | 否      | 对应文件的比较范围，例如 `origin/main...HEAD`；`cached`、`unstaged`、`untracked` 可为空 |
| `old_path`  | 重命名时必填 | 重命名前路径                                                                |
| `hunks`     | 是      | `old_start`、`old_lines`、`new_start`、`new_lines`；未跟踪文件为空数组             |

同一次 `diff` 范围可以同时包含 `cached`、`unstaged` 和 `untracked` 文件。后续阶段必须按 `files[].mode` 决定获取局部变更的方式：
`cached` 使用 `git diff --cached -- <file_path>`，`unstaged` 使用 `git diff -- <file_path>`，`merge_base` / `endpoint` 使用
`range`，`untracked` 直接读取文件内容。

若无法产生 `TARGETS`，必须停止并说明缺失信息，不得进入后续生成阶段。

### 示例

```json
{
  "scope_type": "diff",
  "TARGETS": [
    {
      "file_path": "pkg/order/service.go",
      "target_type": "method",
      "symbol": "(*Service).CreateOrder",
      "locator": "func (s *Service) CreateOrder(ctx context.Context, req *CreateOrderRequest) line 42",
      "source": "diff_hunk",
      "reason": "diff 修改了参数校验分支",
      "hunks": [
        {
          "old_start": 48,
          "old_lines": 3,
          "new_start": 49,
          "new_lines": 6
        }
      ]
    }
  ],
  "diff_context": {
    "files": [
      {
        "file_path": "pkg/order/service.go",
        "status": "M",
        "mode": "merge_base",
        "range": "origin/main...HEAD",
        "hunks": [
          {
            "old_start": 48,
            "old_lines": 3,
            "new_start": 49,
            "new_lines": 6
          }
        ]
      }
    ]
  }
}
```
