# 迭代总结合成流程

每轮迭代修复完成后，生成迭代经验总结，为下一轮修复提供历史参考。

## 流程

### 首轮迭代（ITERATION == 1）

直接拷贝 `fix_summary.md` 作为 `iteration_summary.md`：

```bash
cp $OUTPUT_DIR/iteration_1/fix_summary.md $OUTPUT_DIR/iteration_1/iteration_summary.md
```

首轮不需要 AI 合成，因为只有一轮数据。

### 后续迭代（ITERATION > 1）

需要读取所有历史迭代数据，合成经验总结。

#### 数据收集

对每个迭代 i（从 1 到 ITERATION）：

1. 读取 `$OUTPUT_DIR/iteration_$i/fix_summary.md`
2. 读取 `$OUTPUT_DIR/iteration_$i/test_stats.json`
3. 收集：通过/失败/跳过数量，修复摘要文本

#### 合成总结

基于收集到的所有历史数据，生成经验总结，重点关注：

1. **遇到的问题**：历次迭代中出现了哪些问题
2. **尝试的方案及结果**：哪些修复方案成功/失败/部分成功
3. **需要避免的坑**：例如"修改 X 会导致 Y 出错"、"方案 Z 不可行因为..."
4. **跨迭代的模式**：是否有反复出现的问题模式
5. **测试通过率趋势**：各轮迭代的通过率是在上升还是停滞

#### 输出格式

```markdown
# 迭代经验总结（截至第 N 轮）

## 测试通过率趋势
| 迭代 | 通过 | 失败 | 跳过 | 通过率 |
|------|------|------|------|--------|
| 1    | X    | Y    | Z    | X%     |
| 2    | X    | Y    | Z    | X%     |

## 已解决的问题
- [问题A]：在第 N 轮通过 [修改X] 解决

## 仍然存在的问题
- [问题B]：尝试了 [方案1]、[方案2]，均未解决，原因是...

## 反复出现的模式
- [模式描述]

## 下一轮修复建议
- 避免 [已证实无效的方案]
- 优先尝试 [有希望的方向]
```

#### 写入文件

将总结写入 `$OUTPUT_DIR/iteration_$ITERATION/iteration_summary.md`。

## 注意事项

- 输出经验总结，而非具体的修复指令
- 帮助 Fix Agent 理解历史，避免重蹈覆辙
- 保持简洁，聚焦于可操作的经验
- 不要随意将问题归因于环境问题而不做修复
- 如果某个问题迭代多次仍然出现，要特别强调深入排查
