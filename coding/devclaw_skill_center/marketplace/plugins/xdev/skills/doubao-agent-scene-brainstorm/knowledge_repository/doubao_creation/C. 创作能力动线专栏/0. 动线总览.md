## 二、入口类型差异（重要）

详见 [`../B. Agent 架构专栏/1. 业务架构与场景全景.md`](../B.%20Agent%20架构专栏/1.%20业务架构与场景全景.md) §三。

| 入口 | 意图识别在哪 | 适合需求 |
|---|---|---|
| 主 bot **闲聊** | LLM 层 | 通用 / 灵活；新增能力时主要靠 SP + Tool 描述 |
| 主 bot **指令集 / Action Bar** | 前端结构化 | 高确定性；新增能力时通常加一个 Action Bar 模板 |
| **官方多 bot** | bot 即类型（前端给定） | 专门创作 bot；可能用 bot_engine 映射 |
| **运营多 bot** | bot 配置不同 SP / 模型 | 主题化创作；运营自助配置 |

## 四、动线文件统一格式

每个动线文件包含 7 个章节（参考 [`../../../report_template.md`](../../../report_template.md) § 三 的输出格式）：

```
1. 用户动线（mermaid 序列图）
2. 涉及 PSM 链路（含上下游 RPC）
3. 命中的 Tool（含 schema 路径）
4. 命中的 SP（含 SP key + 4 层加载链状态）
5. 关键 Libra / 切流点
6. 历史架构演进备注（哪一代代码在用）
7. 本期改造影响点（agent_phase_26 改了什么）
```

## 五、与 brainstorm skill 的关联

阶段二 `skill_link_explore` 的子动作 `capability_match` **必须**：

1. 从用户需求关键词命中本表第 § 一 矩阵的某条动线
2. 链向具体动线文件（路径见上）
3. 引用动线的 §1（用户动线）作为该需求"链路穿越点"的底图
4. 引用动线的 §2-§7 作为该需求其他子动作（sp_inventory / libra_inventory / tool_chain_trace / block_protocol_check）的参考依据
