## 一、并存的真相

本期 `agent_phase_26` 是**全新增 + 灰度开关**，老 Plan-Act 链路 `handler/phase3handle/` **未删除**。在灰度 100% 之前：

- C 端用户：按 AB 实验比例分流
- Picasso 评测：按评测 case 配置分流
- **两条链路都有真实流量**

→ **改 Agent 主链路的需求必须双轨分析**。

## 二、灰度判断在哪里

### 2.1 主入口判断（`creation_agent/handler/handler.go`）

```go
if strings.Contains(req.Query.ContentForModel, "2026_bh") || option.SupportAgent26(ctx) {
    // 走新 ReAct（agent_phase_26）
    reactAgent := runtime.NewReactAgent(...)
    return reactAgent.Run(ctx, req)
}
// 否则：老 Plan-Act 链路
err = dispatchResult.AgentHandlerInter.Execute(agentCtx, eventProducer)
```

两个触发条件：
- `req.Query.ContentForModel` 包含 `2026_bh` 标签（评测 / 测试用）
- `option.SupportAgent26(ctx)` 命中 AB 实验（生产灰度）

### 2.2 模型实现的二级灰度

新 ReAct 链路内部还有 `option.SupportAgent26Ark(ctx)` 决定模型实现：

```go
if option.SupportAgent26Ark(ctx) {
    // ArkModel（高性能）
} else {
    // ModelAPIModel（通用）
}
```

详见 [`../../../locators/libra_locator.md`](../../../locators/libra_locator.md) § 三 # 1、# 2。

## 四、并存窗口的常见踩坑

### 踩坑 1：只改新链路，老链路漏改

**症状**：测试新链路看似正常，灰度回退或未灰度的流量出 bug。

**预防**：阶段二链路探索时，按本表对照逐一验证。

### 踩坑 2：只改老链路（如修 bug）但新链路同样代码逻辑漏修

**症状**：本周修一个 bug，下周新链路灰度比例提升后，bug 又出现。

**预防**：bug 修复时**显式判断**这个 bug 是否在 `agent_phase_26/` 也存在，**两边都修**。

### 踩坑 3：以为旧 phase3 是被废弃的，不更新

**症状**：phase3 是第 ④ 代代码（详见 [`./2. 工程架构演进史.md`](./2.%20工程架构演进史.md) § ④）。**它在第 ⑤ 代灰度 100% 前都活跃**，**不是废弃代码**。

**预防**：把 phase3 / agent_phase_26 都当成"活跃代码"对待。

### 踩坑 4：TCC 配置在新老两处都写

**症状**：在 `internal/util/tcc/base.go` 加了配置，没在 `agent_phase_26/tcc/` 加 → 新链路读不到。

**预防**：TCC 配置改动**必须两处都加**，或者明确文档"仅在某一代生效"。

### 踩坑 5：ContextMessage 协议老链路不兼容

**症状**：新链路加 4 路 message 字段，老链路用旧的 `option` 模式取值 → 老链路不感知新字段。

**预防**：详见 [`./4. ContextMessage 4 路扩散.md`](./4.%20ContextMessage%204%20路扩散.md)。

## 五、什么时候老链路才能下线？

PRD 没明说。**保守估计**条件如下：

- [ ] `option.SupportAgent26(ctx)` 灰度比例 100%
- [ ] 灰度期间 P0 故障率 ≤ 老链路水平
- [ ] 多租户隔离落地（Z.2 Gap 表的 gap 项消除）
- [ ] 错误码统一（同上）
- [ ] SP 管理真正收敛到一处（同上）
- [ ] 团队达成共识

## 六、双轨分析模板（写需求时套用）

阶段二 `skill_link_explore` 输出 `link_analysis-<功能点>.md` 时，**按下面双轨格式呈现**：

```markdown
## 6 子动作产出

### entry_locate
- 老链路入口: handler/handler.go::AgentServiceImpl + handler/phase3handle/...
- 新链路入口: handler/handler.go::AgentServiceImpl + agent_phase_26/agent/runtime/agent.go
- 灰度策略: option.SupportAgent26(ctx) (当前 X% 灰度)

### sp_inventory
- 老链路 SP 加载点: internal/rpc/agent_util/sp.go::LoadSPWithDefault
- 老链路 phase3 SP 加载点: internal/rpc/phase3/agent_runtime/sp_manager.go::GetValue
- 新链路 SP 加载点: agent_phase_26/agent/sp/agent_sp.go
- 改动是否需要三处都改：✅/❌

### tool_chain_trace
- 老链路 Tool: internal/rpc/tool.go + phase3/tool/<x>.go
- 新链路 Tool: agent_phase_26/agent/runtime/tool/<x>.go
- 改动是否需要双轨：✅/❌
```
