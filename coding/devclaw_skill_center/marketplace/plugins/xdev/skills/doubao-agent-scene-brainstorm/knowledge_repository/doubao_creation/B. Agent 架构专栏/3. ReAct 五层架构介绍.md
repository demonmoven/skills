## 五、ReAct 协议（关键，决定上下文与解析）

来源：PRD § Agent 执行 § 运行模块。

### 5.1 ReAct vs Plan-Act 协议差异

**Plan-Act**（老）：
1. 第 1 次模型调用：纯 Plan（出 N 步计划）
2. 第 2..N+1 次模型调用：每步 Tool 提参（FC）
3. 最终：N 次 多模态模型调用执行

→ 总共 1+N+N 次 LLM 交互

**ReAct**（新）：
1. 模型一次输出包含 think + 多个 tool_call（XML 协议）
2. 工具串行 / 并行执行
3. 多轮交互通过"模型继续输出"驱动

→ 总共 1~K 次 LLM 交互（K 是反思轮数，常 < N）

### 5.2 XML Tool Call 协议（带 token 围栏）

模型输出示例（`agent_phase_26/agent/runtime/think_stream_parser.go` 解析）：

```xml
<think_never_used_51bce0c785ca2f68081bfa7d91973934>
（模型思考内容，对应 ThinkingBlock 上屏）
</think_never_used_51bce0c785ca2f68081bfa7d91973934>
<seed:tool_call_never_used_51bce0c785ca2f68081bfa7d91973934>
<function_never_used_51bce0c785ca2f68081bfa7d91973934=host>
<parameter_..._=display_text>正在为您生成小猫的图片，请稍等。</parameter_...>
</function_..._=host>
<function_..._=image_gen>
<parameter_..._=output_image_ids><list><item>image_gen_1</item></list></parameter_...>
<parameter_..._=prompts><list><item>小猫</item></list></parameter_...>
<parameter_..._=ratio>1:1</parameter_...>
</function_..._=image_gen>
</seed:tool_call_never_used_51bce0c785ca2f68081bfa7d91973934>
```

**说明**：
- `_never_used_<hash>` 是**模型独享 token 围栏**（防止内容污染），详见 [`../A. 组织职责与找人地图/误区纠正.md`](../A.%20组织职责与找人地图/误区纠正.md) § 误区 7
- 解析器：parsers = `["doubao_think_v1", "doubao_fc_xml_v2"]`
- `host` 是 ReAct 的"宿主"工具，专门用于发 `display_text`（陪伴文本）

### 5.3 加工后的标准 ToolCall 输出

模型原始输出经过 parser 加工后，转化为标准 OpenAI 风格的 tool_calls 数组：

```json
{
    "tool_calls": [
        {"id": "call_xxx", "type": "function", "function": {"name": "host", "arguments": "..."}},
        {"id": "call_yyy", "type": "function", "function": {"name": "image_gen", "arguments": "..."}}
    ]
}
```

详见 PRD § Agent 执行 § 运行模块 行 770+。

## 六、五层之间的"显式协议"（PRD 设计原则）

PRD 强调："各层级之间互相交互时，需要明确定好内部的交互协议，**交互时使用显式的协议进行交互**，避免通过 ctx 的方式传值"。

| 协议 | 在哪里 |
|---|---|
| AgentPayload | 接入层 → 路由层 入口（IDL: `agent.AgentPayload`） |
| ContextMessage（4 路 message） | 接入层 → Agent 逻辑层（详见 [`./4. ContextMessage 4 路扩散.md`](./4.%20ContextMessage%204%20路扩散.md)） |
| ToolCall | Agent 逻辑层 → 创作工具层 |
| 工具产物 | 创作工具层 → Agent 逻辑层（**不直接对接上屏**） |
| WriterPacket | Agent 逻辑层 → 上屏交互层 |
| Block（CreationBlock / ThinkingBlock 等） | 上屏交互层 → Chat 端 |

> **关键约束**：工具层不直接发上屏。这是 PRD 显式声明的边界："创作工具层会将输出结果以统一定义好的产物协议格式返回给 Agent 逻辑层，由 Agent 逻辑层承接后续的反思、上屏输出等模块"。
