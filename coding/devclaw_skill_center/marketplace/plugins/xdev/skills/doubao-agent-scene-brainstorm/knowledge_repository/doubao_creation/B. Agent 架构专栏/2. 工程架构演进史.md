---

## ① 业务萌芽期（2024.3-7）

- 早期 UGC 业务**未单独拆分方向迭代**，最早只有"文生图插件"这一个创作能力
- 代码仅是 **coze 上的一个插件服务**
- 2024 年 4-7 月，逐步引入新创作能力（图生图、文生音乐、分身写真 MVP）

> **代码遗迹**：早期插件方式的代码可能仍存在于 alice_ugc_plugin 等仓库，但本 skill 不覆盖。

---

## ② 基于 Hook 的生图 agent（2024.9）

**起因**：创作迭代越来越多（增加插件、变更 SP 频繁），但都在主 bot 上变更配置 + chat 链路里改创作相关插件 / Action Bar 解析 → **迭代风险高 + 与 chat 耦合深**。

**优点**：
- 生图 SP / 插件独立配置
- Action Bar / extra 解析独立

**缺点**：
- 生图 bot 都需要通过 bot 映射 → 映射到生图 agent → 链路较乱
- agent 中插件还是依赖 bot_engine 调度

> **代码遗迹**：可能仍在某些老 hook 路径中存在。

---

## ③ 豆包新架构下创作 agent（2024.12）

**起因**：豆包做了一次**彻底架构升级**——所有业务方向都以 agent 方式接入豆包。提供了一套回包协议。**此时创作才能彻底做一版独立 agent**，除意图识别外，所有逻辑收敛到创作 agent 内部。

**特征**：
- 创作 agent **独立**（即 `flow.agent.creation`）
- 与 chat 解耦
- 但调度方式偏单体（早期 Plan-Act）

> **代码遗迹**：`creation_agent/handler/` 主链路就是这一代演进的产物。

---

## ④ 多模态创作 agent 探索（2025.3 - 2026 Q1）

**起因**：当前各原子能力还是独立调度的，**缺少联动**（如"画一棵树 → 加一个苹果 → 变成视频"）。

**目标**：充分利用模型泛化能力，**自由编排多个创作原子能力**完成复杂创作需求。

**架构尝试**：
- **Plan-Act**：一次 LLM Plan + N 次 Tool / FC + N 次多模态调用
- **ReAct Agent + Planning** （混合模式）：
  - Planner 出完整计划
  - ReAct Agent 执行计划每步
  - Reviser 反思 + 调整计划

> **代码遗迹**：`creation_agent/internal/rpc/phase3/` 系列代码是这一代的产物（`phase3` = "第三阶段"，承接架构演进 ③）。

---

## ⑤ ReAct + 五层架构（2026 Q2，本期 agent_phase_26）

**起因**：Plan-Act 架构存在 4 类问题：
1. 整体交互复杂（1 Plan + N FC + N 多模态调用），模型消耗高
2. 缺乏灵活调整（Tool 增多导致 SP 控制能力削弱）
3. 复杂 / 多轮任务规划差
4. 工程角度：模块边界趋于模糊混乱，新需求上手成本高

**核心改造**：
- Plan-Act → **ReAct**（模型自己 think + 自动 fc）
- 单体 → **五层架构**：接入层 / 路由层 / Agent 逻辑层 / 创作工具层 / 上屏交互层
- Agent 逻辑层进一步拆：SP 管理 / Skills（RAG + Tool）/ 长短期记忆 / 模型调度

**落地代码**：`creation_agent/agent_phase_26/`（全新增 ~16K 行）

详见 [`./3. ReAct 五层架构介绍.md`](./3.%20ReAct%20五层架构介绍.md)。

## 老代码 vs 新代码命名规则

| 代际 | 标识 | 代码位置示例 |
|---|---|---|
| ③ 豆包新架构 agent（基础） | （无特殊后缀） | `creation_agent/handler/`、`creation_agent/internal/rpc/agent_util/` |
| ④ Plan-Act 探索（phase3） | `phase3` 后缀 | `creation_agent/internal/rpc/phase3/` |
| ⑤ ReAct 五层（本期） | `agent_phase_26` 前缀 | `creation_agent/agent_phase_26/` |

> **关键**：当你在 brainstorm 阶段二做链路探索，看到 `phase3/` 目录就知道是第 ④ 代代码（Plan-Act）；看到 `agent_phase_26/` 就知道是第 ⑤ 代（ReAct）。**两代当前并存**。

## 关于 "phase_26" 命名

- 灰度标签 `2026_bh` 中的 `2026` 同源

> **不要把 26 理解成"第 26 阶段"**。
