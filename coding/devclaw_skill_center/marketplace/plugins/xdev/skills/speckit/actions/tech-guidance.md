# 技术引导输入（交互式）

由主 Agent 直接执行，与用户交互式收集技术指导信息并维护技术引导文档。

## 参数

- `FEATURE_NAME`（必需）：功能特性名称，用于定位 specs 目录

## 入参校验

读取并执行 `<skill_dir>/prompts/resolve_feature_name.md`，传入以下参数：
- `ACTION_TYPE = "other"`
- `ARG = {用户传入的参数}`

执行完成后获得 `FEATURE_NAME`。

推导内部变量：

```text
SPECS_DIR = docs/xdev/speckit/{FEATURE_NAME}
SPEC_DOC = {SPECS_DIR}/spec.md
TECH_GUIDANCE_DOC = {SPECS_DIR}/tech-guidance.md
```

继续校验：

1. `SPEC_DOC` 文件存在
   - 不存在 → 提示用户："`SPEC_DOC` 文件不存在：{路径}，请确认 spec.md 文件是否已生成"

全部校验通过后，进入执行阶段。

## 输出参数

1. `TECH_GUIDANCE_DOC`：`{SPECS_DIR}/tech-guidance.md`，技术引导文档

## 执行流程

### 1. 初始化技术引导文档

检查 `TECH_GUIDANCE_DOC` 文件是否存在：
- 如果不存在，创建一个空文件
- 如果已存在，读取其内容以便后续修改

### 2. 开场提示

向用户输出以下提示，进入技术引导输入模式：

```
现在请您提供技术方案设计的关键输入。例如：

- 技术选型偏好（语言、框架、中间件等）
- 性能要求（QPS、延迟、并发量等）
- 已知技术约束（现有架构限制、兼容性要求等）
- 参考的现有实现或设计模式
- 与其他系统的集成要求

有任何技术指导都可以直接告诉我，我会帮您整理到技术引导文档中。如果暂无额外输入，直接告诉我继续推进即可。
```

### 3. 交互式输入循环

用户会提出技术指导输入或修改意见，每次收到用户的输入后：

1. **整理并写入**：将用户的技术输入结构化整理后，写入/修改 `TECH_GUIDANCE_DOC` 文件。整理时应分类组织（如按技术选型、性能要求、约束条件、集成要求等分节），使其易于后续技术方案设计环节参考
2. **写入后校验**：每次写入文件后，立即用 `Read` 工具回读文件内容，确认写入的中文内容可正常显示、无乱码。如果发现乱码（出现 `�` 或不可读字符），立即删除文件并重新写入
3. **告知用户修改完成**：简要说明整理了什么内容
4. **询问是否继续**：`还有其他技术指导信息要补充吗？`

> 用户可能继续提供输入（重复上述 1-3），也可能表示完毕或要求继续推进（进入步骤 4）。
> 如果用户没有额外输入（直接要求继续推进），确保 `TECH_GUIDANCE_DOC` 文件已存在（空文件即可）。

### 4. 完成技术引导

用户表示完毕或要求继续推进后，输出完成确认：

```
技术引导输入完毕！

产出文件：
- 技术引导文档：{TECH_GUIDANCE_DOC}
```
