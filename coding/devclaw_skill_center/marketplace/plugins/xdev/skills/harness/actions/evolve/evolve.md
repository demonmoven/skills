# Action: evolve —— 知识演进编排

**自身不修改任何代码或文档**。只做三件事：检测、报告、路由建议。

## 核心理念

- **写一次不够，持续演进才是价值**：初始化（`/harness init`）建立骨架，演进（`/harness evolve`）协调持续更新
- **事件驱动，非定期扫描**：文档更新由具体的代码变更事件触发，而非靠人记住去做
- **增量积累，复利效应**：每次小更新的价值随时间累积，最终形成高度精准的仓库知识库

## 路由对象

evolve 的"路由建议"指向 harness skill 自身的 3 个 action：

| 问题类型 | 建议调用 |
|---------|---------|
| 文档与代码不一致 / 模式偏离 / 知识缺口 | `/harness doc-fix` |
| Invariant 违反 / 重复实现 / 技术债 | `/harness debt-fix` |
| 同一规则反复违反 ≥3 次 | `/harness lint-promote` |

## 何时使用

| 场景 | 触发方式 | 说明 |
|------|---------|------|
| 事件驱动 | ExecPlan 完成或检测到结构变更 | 自动评估 7 项命中清单 |
| 定期健康检查 | 用户手动调用 `/harness evolve` | 5 维度健康度报告 |

## 执行方式

读取并按照 `<skill_dir>/actions/evolve/prompts/evolution-triggers.md` 中的完整流程执行。

## 重要约束

**evolve 绝不直接修改代码或文档。** 它的职责边界是：

| 可以做 | 不可以做 |
|--------|---------|
| 检测代码变更事件 | 修改任何源代码文件 |
| 读取文档内容做对比 | 写入或编辑任何文档 |
| 生成健康检查报告 | 执行文档更新操作 |
| 推荐应调用的执行 action | 直接执行 debt-log 记录 |
| 评估 invariant 违反次数 | 编写或修改 lint 规则 |

所有实际修改工作由对应的执行 action 完成（`/harness doc-fix`、`/harness debt-fix`、`/harness lint-promote`）。

## 汇报

完成后向用户汇报：
- 检测到的事件 / 命中的 7 项清单
- 健康度报告（5 维度状态）
- 按优先级排序的"建议执行"清单（每条都明确指向一个 action）
