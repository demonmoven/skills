# Action: lint-promote —— 规范 lint 化

把反复违反的文档级规范升级为自动化 lint 规则。

**核心洞察：lint > docs**——文档可被忽略，但 lint 会阻断提交。将规范从"写在文档里希望被遵守"升级为"写在 lint 里必须被遵守"，是工程实践成熟度的关键一步。

## 何时使用

1. **定期规范审查**：团队每月/每季度执行一次全量扫描
2. **`/harness evolve` 路由触发**：evolve 在更新 debt-log 时发现同一 invariant 被违反 ≥3 次，建议升级
3. **用户手动触发**：用户明确要求"把这条规范变成 lint 规则"

## 混合策略

不是所有规范都能变成 lint 规则——设计级约束只能通过文档和 prompt 强制引用来保障：

| 规范类型 | 检测方式 | 实现形式 | 例子 |
|---------|---------|---------|------|
| 文本级约束 | grep / 正则 | Shell pre-commit hook | 文件长度、命名规范、TODO 格式 |
| 语义级约束 | AST | 原生 linter 规则 | 导入规则、错误处理、跨包引用 |
| 设计级约束 | AI 理解 | 文档 + prompt 强制引用 | 架构风格、模块职责边界 |

## 执行方式

读取并按照 `<skill_dir>/actions/lint-promote/prompts/lint-promote-workflow.md` 中的完整流程执行。

## 汇报

完成后向用户汇报：
- 扫描到的可升级规范清单（按类型分类）
- 选中升级的规范（含降级路径：docs → hook → linter）
- 生成的 lint 规则文件清单
- 验证结果（lint 规则是否能正确检测出原违反案例）
