## 根因分类框架

诊断输出时，优先归到以下一级分类之一；必要时同时给出标准枚举值，便于后续统计和聚类。

### 1. 请求参数问题

- 枚举值：`request_error`
- 典型信号：必填缺失、类型错误、字段格式非法、测试数据不存在
- 建议动作：修正请求参数、补测试数据、重新发起请求

### 2. Mock 数据问题

- 枚举值：`mock_error`
- 典型信号：当前存在 Mock，且请求或响应表现与真实契约不一致
- 建议动作：检查 Mock 规则、Mock 命中条件、Mock 返回结构

### 3. IDL / 契约问题

- 枚举值：`idl_contract_error`
- 典型信号：方法不存在、字段缺失、类型不符、响应结构与预期不一致
- 建议动作：检查 `<IDL_BRANCH>`、BAM 版本、请求侧与运行时侧 IDL 一致性

### 4. 环境部署问题

- 枚举值：`env_deploy_error`
- 典型信号：无实例、版本未生效、泳道或集群不匹配、目标环境未准备好
- 建议动作：检查 `<ENV>`、`<CLUSTER>`、`<VDC>`、实例部署状态

### 5. 流量路由或通信问题

- 枚举值：`traffic_route_error`、`communication_error`
- 典型信号：超时、连接失败、`CP_EMPTY_ENDPOINT`、RPC 1701、403、Mesh 路由异常
- 建议动作：排查目标实例是否可达、流量是否进入目标环境、权限与路由是否正确

### 6. 服务代码问题

- 枚举值：`service_code_error`
- 典型信号：HTTP 5xx、panic、SQL 错误、空指针、业务逻辑异常
- 建议动作：定位到服务端代码、方法、日志位置，必要时关联最近变更

### 7. 配置或数据问题

- 枚举值：`config_error`、`data_error`
- 典型信号：TCC 缺失、配置漂移、数据库无数据、缓存异常
- 建议动作：补配置、造数、检查依赖配置是否在当前环境生效

### 8. 下游依赖问题

- 枚举值：`dependency_error`
- 典型信号：主调接口失败，但根因在下游服务、依赖环境或依赖配置
- 建议动作：区分主服务问题与下游问题，必要时补充下游证据

### 9. 误报或噪音

- 枚举值：`false_positive`
- 典型信号：日志有 error 但响应正确，或失败与被测对象无直接关系
- 建议动作：降噪，不要直接透出为服务缺陷

### 10. 暂无法归因

- 枚举值：`unknown`
- 典型信号：关键证据缺失，无法可靠判断
- 建议动作：明确缺口，给出补证建议，不强行定案

## 推荐报告结构

每次输出尽量遵循以下结构。

### 1. 一句话结论

一句话说明本次结果更像什么问题，不像什么问题。

### 2. 根因分类

同时输出中文分类和标准枚举值，例如：

- 环境部署问题 / `env_deploy_error`
- IDL / 契约问题 / `idl_contract_error`

### 3. 证据摘要

只保留最强的 2 到 4 条证据，不要堆砌数据。

### 4. 关键日志或诊断结论

优先保留最能支撑结论的诊断摘要；若没有额外现场证据，则只保留关键错误信息、核心现象和归因判断。

### 5. 修复或补测建议

明确告诉用户优先做什么，而不是泛泛而谈。

### 6. 是否建议重新执行测试

必须明确回答以下三类之一：

- 可以立即重试
- 需要修复后再重试
- 当前重试价值不高

### 7. 置信度与数据缺口

若证据不完整，必须明确写出：

- 置信度：`high / medium / low`
- 缺失了哪些证据
- 为什么当前不能更强结论

## 输出模板

### 模板一：结果摘要版

适用于仅输出结果摘要，或用户未要求深度分析的场景：

```md
### 一句话结论
- <本次结果更像什么问题，不像什么问题>

### 测试结果摘要
- 测试对象：<psm> / <method>
- 测试环境：<VRegion> / <ENV 或 IPport>
- 执行结果：成功 / 失败
- 状态信息：HTTP <status_code> / Biz <biz_status_code>
- 耗时：<duration>
- LogID：<logid 或 未获取到>
- 关键信号：<关键响应字段或关键错误信息>

### 初步归类
- 根因分类：<中文分类> / <enum>

### 下一步建议
- <建议 1>
- <建议 2>

### 置信度与缺口
- 置信度：<high / medium / low>
- 数据缺口：<缺失的证据>
```

### 模板二：综合诊断版

适用于已完成 doctor 证据链诊断，且具备较完整证据的场景：

```md
### 一句话结论
- <本次问题更像什么，不像什么>

### 根因分类
- <中文分类> / <enum>

### 证据摘要
- <最强证据 1>
- <最强证据 2>
- <最强证据 3>

### 问题分析结论
- <基于测试结果、上下文和证据链诊断得到的关键结论>

### 处理建议
- <建议 1>
- <建议 2>
- <建议 3>

### 是否建议重试
- <立即重试 / 修复后重试 / 当前不建议重试>

### 置信度与缺口
- 置信度：<high / medium / low>
- 数据缺口：<缺失的证据或仍未验证的点>
```
