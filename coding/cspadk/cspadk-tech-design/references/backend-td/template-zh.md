# 泳道

> **泳道 = 路由头**（`X-TT-ENV` / RPC 环境标签）附加到 HTTP 和 RPC 调用上，使 boe/ppe 流量落到正确的隔离测试实例。约定：`{env}_{feature_slug}`，其中 `env ∈ {boe, ppe}`，`feature_slug` 是描述**功能**的简短 snake_case 标识符，而非 PSM（PSM 名称太长且跨功能共享）。
>
> **硬性规则 — 违规会导致测试环境路由失效：**
> 1. `{feature_slug}` 在各环境中必须**字节一致**（`boe_` 和 `ppe_` 使用相同 slug）。`boe_ai_chatbot` + `ppe_ai_summary` 是错误的。
> 2. Slug 正则：`^[a-z][a-z0-9_]{1,29}$` — 以字母开头，snake_case，总长度 ≤30 字符（env 前缀计入路由标签长度上限）。
> 3. 完整泳道正则：`^(boe|ppe)_[a-z][a-z0-9_]{1,29}$`。
> 4. 不要列出 `prod_*` 泳道 — prod 没有泳道（它是默认的无标签路由）。只有 boe 和 ppe 需要条目。
> 5. 一个 TD 一个 slug。除非功能确实跨越独立测试的子系统（罕见），否则不要将功能分散到多个泳道。

- boe_<feature_slug>
- ppe_<feature_slug>

# IDL / API 变更  [M+, 无 IDL 变更时省略]

**接口 IDL 完整定义** — 对本需求涉及的所有接口（含新增、修改、已有但被调用），逐一列出完整的请求/响应参数 IDL，以便前端制定技术方案。每个接口使用如下格式：

```thrift
// PSM: <psm>
service <ServiceName> {
    // 方法描述
    <Response> <methodName>(1: <Request> req)
}

struct <Request> {
    1: required i64 id          // 字段描述
    2: optional string name     // 字段描述
    3: required list<i64> ids   // 字段描述
}

struct <Response> {
    1: required bool success    // 字段描述
    2: optional string message  // 字段描述
}
```

要求：
- 每个字段标注序号、required/optional、类型、中文描述
- 枚举类型列出所有枚举值及含义
- 嵌套 struct 递展开至叶子字段
- 已有接口被本需求调用但无变更的，也需列出完整 IDL（前端无历史上下文）
- 修改的接口同时标注变更类型：`[新增字段]`、`[修改字段]`、`[废弃字段]`

**Thrift IDL Diff** — 对每个新增/修改/废弃的方法，展示 before→after 代码块和一行向后兼容声明。

**错误码**

| 错误码 | 含义 | 何时抛出 | 调用方预期行为 |
|---|---|---|---|

**向后兼容** — 一句话：旧客户端是否仍能工作？若不能，调用方迁移计划。
