## 泳道

> **泳道 = 路由头**（`X-TT-ENV` / RPC 环境标签）附加到 HTTP 和 RPC 调用上，使 boe/ppe 流量落到正确的隔离测试实例。约定：`{env}_{feature_slug}`，其中 `env ∈ {boe, ppe}`，`feature_slug` 是描述**功能**的简短 snake_case 标识符，而非 PSM（PSM 名称太长且跨功能共享）。
>
> **硬性规则 — 违规会导致测试环境路由失效：**
> 1. `{feature_slug}` 在各环境中必须**字节一致**（`boe_` 和 `ppe_` 使用相同 slug）。`boe_ai_chatbot` + `ppe_ai_summary` 是错误的。
> 2. Slug 正则：`^[a-z][a-z0-9_]{1,29}$` — 以字母开头，snake_case，总长度 ≤30 字符（env 前缀计入路由标签长度上限）。
> 3. 完整泳道正则：`^(boe|ppe)_[a-z][a-z0-9_]{1,29}$`。
> 4. 不要列出 `prod_*` 泳道 — prod 没有泳道（它是默认的无标签路由）。只有 boe 和 ppe 需要条目。
> 5. 一个 TD 一个 slug。除非功能确实跨越独立测试的子系统（罕见），否则不要将功能分散到多个泳道。
> 6. 前端泳道必须与后端 TD 的 `feature_slug` 一致 — FE 和 BE 共享同一泳道。

- boe_<feature_slug>
- ppe_<feature_slug>
