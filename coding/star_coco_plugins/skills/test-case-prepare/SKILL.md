# 接口测试用例准备 Skill

## 适用场景
- OpenSpec 变更已沉淀在 `openspec/changes/<id>/`，需要基于 proposal/design/tasks/spec deltas 生成可执行的接口测试用例
- 在执行接口测试前，需要先设计/整理测试用例并让用户确认
- 需要把用例以 markdown 结构化输出，便于后续逐条执行与回填结果

## 约束（必须遵守）

- **只做冒烟测试**：覆盖核心主路径 + 关键异常路径 + 少量关键边界，确保主要接口能跑通
- **禁止引用单测**：不要参考或复用任何 `_test.go`（它们是单元测试，不是接口行为测试）
- **接口级粒度**：围绕 IDL / HTTP 接口定义与入出参做用例，不关注内部实现细节
- **用例内容中文**：产出的 `test_plan.md` 必须使用中文描述
- **严格基于 IDL 设计入参/出参**：`请求关键参数` / `预期结果` 必须与接口定义一致

## 测试用例准备流程（OpenSpec changes 驱动）

1. 定位变更目录：`openspec/changes/<id>/`
2. 阅读并理解变更：
   - `openspec/changes/<id>/proposal.md`
   - `openspec/changes/<id>/design.md`（如存在）
   - `openspec/changes/<id>/tasks.md`
   - `openspec/changes/<id>/specs/**/spec.md`（本次变更影响到的 spec/接口差异）
3. 枚举受影响的接口（新增/修改/依赖变更）与关键业务规则
4. 按接口逐条产出用例：
   - 核心主路径（Happy Path）
   - 使用 `database-toolbox` skill 从测试数据库中查询合适的测试数据：
     ```
        /db-query
        SELECT <fields> FROM <table> WHERE <conditions> AND delete=0 LIMIT 10;
     ```
   - 主要异常路径（参数非法/权限/状态不满足/幂等冲突等）
   - 关键边界（空列表/不存在/极值/分页边界等，挑最关键的即可）

5. 将用例记录到：`openspec/changes/<id>/test_plan.md`
6. **必须**：先让用户确认 `test_plan.md` 再进入执行阶段（例如交给 `deploy-and-test` 逐条执行并回填结果）

## 标准用例格式（test_plan.md）

`openspec/changes/<id>/test_plan.md` 中的用例必须使用如下 markdown 表格结构（每行一条用例）：

| 用例名 | 关联接口 | 前置条件与数据准备 | 请求关键参数 | 预期结果 | 校验点 |
|---|---|---|---|---|---|

## 标准测试矩阵（用于每个接口的用例补全）

根据接口类型，按以下模板补齐用例。实际用例的 `请求关键参数` / `预期结果` 以 `openspec/changes/<id>/specs/**/spec.md` 对应的接口/IDL 为准。

### 写接口（CREATE/关联/新增类）标准用例

| 用例名 | 关联接口 | 前置条件与数据准备 | 请求关键参数 | 预期结果 | 校验点 |
|---|---|---|---|---|---|
| 必填参数缺失-逐个置空 | `<接口名>` | 无/或准备一条合法的基础数据 | 逐个将必填字段置空（其余字段保持合法） | 返回参数错误（ErrParamIllegal/ErrParamRequired 或等价错误码） | 错误码/错误信息准确；未产生脏数据 |
| 正常创建/关联成功 | `<接口名>` | 准备可用的关联对象/外键数据；必要时用 `database-toolbox` 获取合法 ID | 提供一组完整且合法的关键参数（ID/必填字段/业务字段） | 返回成功（StatusCode=0 或等价语义），并返回新对象 ID/关键字段 | 响应字段正确；DB 可查到新记录且关键字段与请求一致 |
| 重复/冲突 | `<接口名>` | 先执行一次“正常创建/关联成功”得到已存在的数据 | 使用相同的唯一键/幂等键/冲突条件再次请求 | 返回对应业务错误码（如 ErrAlreadyExist/ErrConflict/ErrDuplicate） | 错误码符合约定；DB 无重复写入 |
| 权限/状态不满足（如适用） | `<接口名>` | 准备无权限用户/不满足状态的目标对象 | 关键参数保持合法，仅触发权限/状态条件 | 返回权限/状态相关错误（如 ErrNoPermission/ErrInvalidStatus） | 错误码准确；DB 未发生变更 |

### 读接口（GET/LIST类）标准用例

| 用例名 | 关联接口 | 前置条件与数据准备 | 请求关键参数 | 预期结果 | 校验点 |
|---|---|---|---|---|---|
| 必填参数缺失 | `<接口名>` | 无 | 关键 ID/分页参数等必填字段置空或缺失 | 返回参数错误 | 错误码/错误信息准确 |
| 正常查询-命中 | `<接口名>` | 准备一条已存在的数据（用 `database-toolbox` 找到合法 ID） | 传入存在的 ID/合法筛选条件 | 返回成功且包含目标数据 | 返回字段完整且符合 IDL；关键字段与 DB 一致 |
| 查询不存在-空结果/NotFound | `<接口名>` | 无 | 传入不存在的 ID/筛选条件 | 返回空结果或 NotFound（以接口定义为准） | 空结果结构正确；错误码符合约定（如有） |
| 分页边界（LIST 如适用） | `<接口名>` | 准备足够多的数据或选择有多条记录的条件 | page=1,page_size=N；以及边界 page_size=1/最大值；或 page 超范围 | 返回分页结构正确；超范围返回空列表/最后一页（以接口定义为准） | total/has_more/next_cursor 等分页字段一致；列表长度符合 page_size |

### 更新接口（UPDATE类）标准用例

| 用例名 | 关联接口 | 前置条件与数据准备 | 请求关键参数 | 预期结果 | 校验点 |
|---|---|---|---|---|---|
| 必填参数缺失 | `<接口名>` | 无 | ID 或关键字段置空/缺失 | 返回参数错误 | 错误码/错误信息准确；DB 未变更 |
| 正常更新 | `<接口名>` | 准备一条存在的数据（用 `database-toolbox` 找到合法 ID） | 传入存在的 ID + 合法的更新字段（避免全量覆盖不允许字段） | 返回成功（StatusCode=0 或等价语义） | DB 中对应字段已变更；未更新字段保持不变（以接口语义为准） |
| 目标不存在 | `<接口名>` | 无 | 使用不存在的 ID 发起更新 | 返回 NotFound/空影响（以接口定义为准） | 错误码符合约定；DB 无新增/无误更新 |
| 状态冲突/并发（如适用） | `<接口名>` | 准备状态不允许更新的目标对象或旧版本号 | 触发状态/版本冲突条件（如 version/etag 不匹配） | 返回冲突错误（如 ErrConflict/ErrInvalidStatus） | 错误码准确；DB 未被错误覆盖 |
