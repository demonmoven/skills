# Gloop 首页优化 Spec v0.1

> 基于当前代码实现（focus / board / list 三形态）的重新 Review，对照 refactor-spec-v1 / hotl-spec-v0.1 / design-phase-spec-v0.1 三份后端架构 spec，输出首页（Quests 入口页）的优化方向与实施规格。

> 说明：本文件保留为早期思路归档。当前实现对齐和后续路线以 `homepage-optimization-spec-v0.2.1.md` 为准；不要再按本 v0.1 的 emoji、批量操作、trust tier 控制面等表述判断实现状态。

## 1. 当前实现现状评估

### 1.1 三形态概览

当前首页 (`QuestsBoard.tsx`) 已实现三种视图模式，共享数据层与 QuestCard 组件，差异在布局与信息密度：

| 模式 | 定位 | 核心布局 | 信息密度 | 默认分组 |
|------|------|----------|----------|----------|
| **Focus** | 指挥中心 / 每日第一眼 | 双列：需关注 + 进行中 + 近期结果 | 中（卡片） | 按优先级（attention priority） |
| **Board** | 全局看板 / 流程视角 | 水平滚动看板，按状态分列 | 中低（卡片） | 按状态（status kanban） |
| **List** | 高密度列表 / 批量处理 | 垂直分组列表，行式布局 | 高（行） | 按状态（attention 优先） |

### 1.2 做得好的地方 ✅

1. **三形态分层清晰**：从"盯盘"（focus）→"全局"（board）→"批量"（list），覆盖不同使用场景
2. **状态可视化完整**：9+ 种 quest 状态均有对应视觉标识（颜色点 / 侧边栏 / 边框）
3. **Focus 优先级排序**：`focusPriority()` 按 user_review > blocked > apply_failed > waiting_input 排序，符合人在回路的注意力分配
4. **实时更新**：SSE 全局流 + 250ms 防抖刷新，状态变化近实时
5. **筛选/排序/分组体系完整**：groupBy（status/type/none）、sortBy、visibleFields 可配
6. **移动端适配**：多断点响应式，抽屉式导航
7. **Attention 机制**：user_review / blocked / apply_failed 有 amber 左侧强调条，视觉层次明确

### 1.3 核心问题：与三份架构 Spec 的 Gap

当前首页本质上仍是"任务列表视图"，面向的是 **2 阶段简单循环**（执行 → 评审）。三份后端重构 spec 引入的核心概念，在首页上几乎没有承载：

| 架构能力 | 首页现状 | 缺失影响 |
|----------|----------|----------|
| **阶段流水线（Phase Pipeline）** | 只展示状态，无阶段概念 | 用户看不到 quest 处于哪个 phase、离出口还有多远、返工历史 |
| **结构化产物（Artifact）** | 卡片只显示 query 文本 | 用户看不到设计方案 / 评审报告 / diff 等产物摘要 |
| **HOTL 策略引擎** | 完全不可见 | 用户不知道信任层级、为什么停了、自动做了什么 |
| **信任层级（Trust Tiers）** | 无体现 | tier_0 ~ tier_3 的自动化程度无感知 |
| **全局安全底线** | 无提示 | workspace_diff / allow_l2 / external_side_effect 强制人工审核的原因不透明 |
| **恢复策略（Recovery）** | blocked 只展示原因 | 重试次数、降级路径、是否可自动恢复均不可见 |
| **Waiting Input** | 归在"需关注"里 | 与 blocked 混放，agent 问了什么、等多久了不直观 |
| **设计阶段（Design Phase）** | 只有 type=design 标签 | 4 阶段流水线（设计→设计评审→执行→实现评审）完全不可见 |
| **设计产物** | 无预览 | design_plan 作为一等公民，在首页没有任何体现 |

## 2. 优化目标与原则

### 2.1 设计目标

1. **承载架构能力**：让 refactor-spec 的核心概念（阶段流水线、HOTL、设计阶段）在首页可感知、可操作
2. **保持三形态分层**：不推翻现有 focus / board / list 框架，在每层上做增量增强
3. **渐进式暴露复杂度**：默认简洁，需要时可展开，不破坏"轻量首页"体验
4. **强化指挥中心价值**：Focus 视图是每日入口，要让用户一眼知道"现在该做什么、系统在做什么、有没有风险"

### 2.2 设计原则

- **默认简洁，按需展开**：核心信息一目了然，详情点击/hover 查看
- **语义化视觉**：每种架构概念有对应的视觉语言（颜色、图标、位置），保持一致
- **操作就近**：能在列表/看板上操作的，不一定要进详情页
- **信任透明**：自动化做了什么、为什么停了、什么时候需要人，清晰可见

## 3. 详细优化方案

### 3.1 Focus 视图优化：从"待办列表"到"指挥中心"

#### 现状问题
当前 Focus 视图是"需关注 + 进行中 + 近期结果"的三栏堆叠，本质上是个优先级排序的任务列表。缺少：
- 系统整体运行状态的感知（有多少在自动跑、多少停了、信任层级分布）
- HOTL 策略在做什么的感知
- 设计任务的独立存在感

#### 优化方案

**3.1.1 顶部状态区增强（Pipeline Status Header）**

现有 4 个状态药丸（待执行 / 执行中 / 评审中 / 需关注），增强为**分层状态面板**：

```
┌─────────────────────────────────────────────────────────────────┐
│  🎯 今日概览                        ⚙️ 自动运行中: 5 个          │
│  待处理 3 · 进行中 8 · 已完成 12     信任层级: t2 平均           │
├─────────────────────────────────────────────────────────────────┤
│  [待执行 3]  [执行中 5]  [评审中 2]  [需关注 3]  [已完成 12]   │
└─────────────────────────────────────────────────────────────────┘
```

- 增加"自动运行中"计数（处于 tier_2/tier_3 自动运行的 quest 数）
- 增加"平均信任层级"指标，反映系统自动化程度
- 状态药丸可点击，点击跳转到 Board 视图对应列

**3.1.2 "需关注"分区细化**

现有一个大的"需关注"列表，拆分为**四个语义分区**，每个分区有独立的标题和操作入口：

| 分区 | 包含状态 | 视觉标识 | 操作 |
|------|----------|----------|------|
| 🔍 **等待审核** | user_review | 琥珀色标签 | 一键审核（跳详情） |
| ❓ **等待输入** | waiting_input | 琥珀色标签 + 对话图标 | 快速答复（内联回复框） |
| 🚧 **已阻塞** | blocked | 红色标签 | 排查 / 跳过 |
| ⚠️ **应用失败** | apply_failed | 红色标签 | 重试 / 查看错误 |

每个分区都是独立的折叠块，空状态自动隐藏。分区顺序按优先级排列（同 focusPriority 逻辑）。

**3.1.3 新增"系统自动运行中"模块**

在"进行中"模块上方，增加一个轻量模块，展示当前正在自动推进的 quest：

```
🤖 自动运行中 (3)
  ├─ #a1f3 重构登录模块          t2 · 战士执行中 · 第 3 回合
  ├─ #b8c2 生成 API 文档         t3 · 法师评审中
  └─ #d9e1 代码风格统一          t2 · 自动重试第 2 次
```

- 展示信任层级徽章（t0~t3）
- 展示当前阶段（不是状态，是 phase）
- 展示自动重试/降级等 recovery 动作
- 点击卡片进入详情

**3.1.4 设计任务独立分区**

设计类 quest（type=design）在"进行中"和"近期结果"中混在一起，不容易区分。增加：

- 设计阶段的任务卡片带有**紫色渐变边框**和 📐 图标
- "进行中"内部分组：执行中（战士） / 设计中（战士设计） / 评审中（法师评审）
- 已完成的设计任务显示"设计方案已产出"标签，可快速预览方案摘要

---

### 3.2 Board 视图优化：承载阶段流水线

#### 现状问题
当前 Board 是**按状态**分列的传统看板，而 refactor-spec-v1 的核心是**按阶段**驱动的流水线。状态（status）是执行层面的，阶段（phase）是流程层面的，二者维度不同。

#### 优化方案

**3.2.1 看板双模式：状态视图 / 阶段视图**

在 Board 工具栏增加一个切换：**按状态看（默认） / 按阶段看**

- **按状态看**：保持现状，10 列（pending → success），面向执行监控
- **按阶段看**：根据 quest 的当前 phase 分列，面向流程理解

**阶段视图列（以设计型 quest 为例）**：
```
[ 战士设计 ] → [ 法师设计评审 ] → [ 战士执行 ] → [ 法师实现评审 ] → [ 用户审核 ] → [ 完成 ]
```

**阶段视图列（以执行型 quest 为例）**：
```
[ 战士执行 ] → [ 法师评审 ] → [ 用户审核 ] → [ 完成 ]
```

- 每列顶部显示该阶段的平均耗时（从历史数据计算）
- 每张卡片显示在当前阶段的停留时间
- 返工卡片带有 ↺ 图标和返工次数标记

**3.2.2 卡片增强：阶段进度 + 产物摘要**

在 Board 视图的卡片上（hover 或展开时）显示：
- **阶段进度条**：当前 phase 在整个流水线中的位置（如 "3/4 阶段"）
- **产物标签**：如果当前阶段已产出 artifact，显示对应标签（📄 设计方案 / 📝 评审报告 / 🔄 diff 等）
- 点击产物标签可快速预览（弹窗内显示摘要，不进详情页）

**3.2.3 列内分组：信任层级**

每列内部可按信任层级分组（折叠/展开），快速看出哪些是自动的、哪些需要人：

```
用户审核列
├─ 🔴 t0 (手动)    2 个
├─ 🟡 t1 (确认运行) 1 个
├─ 🟢 t2 (自动+审)  3 个
└─ 🟣 t3 (全自动)   0 个
```

这个分组是可选的，通过工具栏的"分组"按钮切换（status / type / trust_tier / none）。

### 3.3 List 视图优化：高密度 + 批量操作

#### 现状问题
List 视图信息密度最高，但缺少：
- 批量操作能力（批量审核 / 批量跳过等）
- 阶段维度的信息
- 与 HOTL 相关的列

#### 优化方案

**3.3.1 增加批量操作**

- 每行前面增加复选框（默认隐藏，进入"批量模式"后显示）
- 工具栏增加"批量操作"按钮，点击进入批量模式
- 支持的批量操作（取决于选中项的状态）：
  - 批量通过审核（user_review 状态）
  - 批量跳过阻塞（blocked 状态，需确认）
  - 批量取消（pending/running 状态）
  - 批量调整信任层级

**3.3.2 新增可显示列**

在 FieldsPopover 中增加以下可选列：
- **当前阶段**（phase name）
- **信任层级**（t0~t3 徽章）
- **返工次数**（已有，确认显示）
- **产物数**（artifact count）
- **阻塞原因分类**（infra / logic / budget 等）

**3.3.3 按阶段分组**

groupBy 增加"按阶段"选项，与 Board 的阶段视图对应。

### 3.4 HOTL 可视化增强

这是整个优化中**价值最大但工作量也最大**的部分。HOTL 不是一个页面，是一种**渗透在每个状态中的信息层**。

#### 3.4.1 信任层级徽章（全局）

设计一套 t0~t3 的视觉标识：

| 层级 | 标签 | 颜色 | 含义 |
|------|------|------|------|
| t0 | ⏸️ T0 | 灰色 | 已暂停 / 完全手动 |
| t1 | ✋ T1 | 琥珀色 | 确认后运行（每步需确认） |
| t2 | 🤖 T2 | 蓝色 | 自动运行 + 人工审核 |
| t3 | ⚡ T3 | 绿色 | 全自动（信任最高） |

- 所有 quest 卡片/行的右上角显示当前信任层级徽章
- 点击徽章可快速调整层级（弹出菜单：t0 / t1 / t2 / t3）
- 调整时有确认提示，说明调高/调低的影响

#### 3.4.2 "为什么停了"透明化

对于 user_review / blocked / waiting_input 状态的 quest，卡片上增加一个**"🛡️ 停止原因"**提示（hover 显示详情）：

- **安全底线触发**："因包含外部副作用，需人工审核" / "因 L2 权限，需人工审核"
- **策略触发**："按 T2 策略，执行完成后需审核"
- **资源耗尽**："达到最大回合数（100）" / "达到最大时长（30min）"
- **Agent 问询**："战士提问：xxx 方案选哪个？"
- **执行错误**："API 调用失败：xxx"

这个信息来自后端的 `blocked_reason` / `failure_attribution` / `waiting_input` 数据，当前已有部分数据但前端展示不充分。

#### 3.4.3 恢复策略可视化

对于 blocked 状态的 quest，如果系统已自动执行了 recovery 动作，展示恢复历史：

```
🔴 已阻塞
原因: 模型调用超时
恢复: 已自动重试 2/3 次 ↺↺⏳
下次尝试: 30秒后
```

- 显示已重试次数 / 最大重试次数
- 显示使用的恢复策略（retry / degrade / escalate / skip_phase）
- 如果策略是 escalate，显示"已升级至人工处理"
- 可点击"立即重试"或"跳过此阶段"

#### 3.4.4 全局安全底线提示

在 Focus 视图顶部增加一个**轻量提示条**（不打扰，可收起）：

```
🛡️ 安全底线: 包含 workspace_diff / L2 权限 / 外部副作用的操作
            将始终要求人工审核，不受信任层级影响
```

点击可展开查看详细规则。首次出现时显示，之后默认收起。

### 3.5 设计阶段可视化增强

#### 3.5.1 设计任务的视觉区分

- 设计类 quest 在卡片上有 📐 图标 + 紫色调视觉元素
- 状态标签改为设计阶段语义：
  - 战士设计中（而非执行中）
  - 法师设计评审中（而非评审中）
  - 设计方案已完成（阶段性完成标记）

#### 3.5.2 设计产物快速预览

- 设计完成的 quest 卡片底部显示"📄 设计方案"标签
- 点击标签弹出设计方案摘要预览（标题 + 核心要点 + 查看详情链接）
- 设计评审中的 quest 显示"👀 法师评审中"，hover 显示评审进度

#### 3.5.3 设计 → 执行的流转

- 设计评审通过后，卡片上显示"✅ 设计已通过 → 待执行"
- Board 视图的阶段模式中，能清晰看到 quest 从"设计评审"列移动到"战士执行"列
- Focus 视图的"近期结果"中，设计完成的任务单独分组（"近期完成的设计"）

### 3.6 通用交互优化

#### 3.6.1 卡片 Hover 操作栏

所有视图的 quest 卡片/行，hover 时显示**快速操作按钮**（无需进入详情页）：

- **user_review**：通过 / 驳回 / 查看 diff
- **blocked**：重试 / 跳过 / 查看原因
- **waiting_input**：快速答复
- **running**：暂停 / 停止
- **pending**：立即开始 / 取消

操作确认使用轻量 toast 或 inline 确认，不弹大对话框。

#### 3.6.2 空状态优化

当前 Focus 视图有较丰富的空状态，Board 和 List 视图的空状态需要增强：
- Board 空状态：展示流程示意图 + "发起第一个委托" CTA
- List 空状态：同 Focus，保持体验一致

#### 3.6.3 键盘快捷键

- `1/2/3` 切换 focus/board/list 视图
- `n` 新建委托
- `/` 搜索
- `b` 批量模式

## 4. 信息架构调整

### 4.1 侧边栏导航（保持不变）

现有导航结构合理，不做调整：
委托 → 收件箱 → 自动化 → 知识 → 冒险者 → 技能 → 提示词 → 统计

### 4.2 首页定位

首页（Quests 入口）的定位从"任务列表"升级为**"循环指挥中心"**：
- 一眼看全系统运行状态
- 快速处理需要人工介入的事项
- 了解各阶段流转情况
- 管理自动化信任程度

## 5. 实施路线图

按优先级分三阶段实施：

### 阶段一：基础增强（P0，价值高、成本低）
1. **"需关注"分区细化**：将 focus 视图的需关注拆分为 4 个语义分区
2. **信任层级徽章**：在卡片上显示 t0~t3 徽章（如果后端已返回数据）
3. **"为什么停了"透明化**：增强 blocked / user_review / waiting_input 的原因展示
4. **快速操作按钮**：卡片 hover 显示常用操作
5. **状态药丸可点击**：点击跳转到 Board 对应列

### 阶段二：流水线可视化（P1，价值中、成本中）
1. **看板阶段视图**：增加按 phase 分列的看板模式
2. **阶段进度条**：卡片上显示当前阶段在流水线中的位置
3. **产物标签与预览**：artifact 摘要标签 + 快速预览弹窗
4. **设计任务视觉区分**：紫色系 + 阶段语义标签
5. **List 视图批量操作**：复选框 + 批量操作栏

### 阶段三：HOTL 深度整合（P2，价值高、成本高）
1. **恢复策略可视化**：重试次数、策略类型、自动恢复倒计时
2. **信任层级快速调整**：点击徽章直接调整
3. **全局安全底线提示条**：首次展示 + 可收起
4. **按信任层级分组**：groupBy 增加 trust_tier 选项
5. **Focus 视图系统状态面板**：自动化运行数、平均信任层级
6. **Waiting Input 快速答复**：内联回复框，不进详情页

## 6. 后端依赖

以下优化需要后端 API 配合（需确认当前是否已支持）：

| 优化项 | 所需后端数据 | 当前状态 |
|--------|-------------|----------|
| 信任层级徽章 | quest.trust_tier 字段 | 待确认 |
| 阶段视图 | quest.current_phase / phase_def 列表 | refactor-spec-v1 应有 |
| 产物标签 | quest.artifacts 摘要列表 | refactor-spec-v1 结构化产物应有 |

## 7. 设计规范补充

### 7.1 颜色体系（沿用现有，新增语义）

保持现有 Mew 风格（黑/白/灰 + 单强调色），新增 HOTL 相关语义色：

- **T0 灰色**：`--ink-30` / `--ink-50`（已暂停/手动）
- **T1 琥珀色**：`--attention`（已有人工确认，沿用现有 attention 色）
- **T2 蓝色**：`--brand`（自动+审核，用主品牌色）
- **T3 绿色**：`--success`（全自动，用成功色）

- **设计紫色**：`--mage-violet`（设计类任务强调色，法师色）

### 7.2 图标体系

- 🤖 自动化相关
- 🛡️ 安全底线 / 保护
- ⏸️ 暂停 / 手动
- ↺ 重试 / 返工
- 📐 设计方案
- 📄 产物 / 文档
- ❓ 等待输入 / 提问
- ⚡ 高速 / 全自动

### 7.3 动效

- 状态切换：轻量 fade + slide（< 200ms）
- 自动运行中卡片：轻微呼吸动效（表示"系统在工作"）
- 新需关注项出现：琥珀色闪烁一次（吸引注意但不打扰）

## 8. 成功度量

优化上线后，通过以下指标评估效果：

1. **首页停留时间**：预期下降（用户更快找到要做的事）
2. **需关注处理率**：预期上升（更清晰的分区 + 快速操作）
3. **进入详情页比例**：预期下降（更多操作在首页完成）
4. **信任层级调整次数**：作为 adoption 指标（用户理解并使用 HOTL）
5. **用户反馈**：NPS 或定性反馈，关于"系统状态是否清晰"
